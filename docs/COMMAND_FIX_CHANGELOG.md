# 命令修复说明

## 修复日期
2025-12-04

## 修复问题
所有 `*-start` 命令（`/pm-start`, `/be-start`, `/fe-start`, `/qa-start`, `/ops-start`, `/tl-start`, `/start-task`）在创建线程后**没有立即执行角色工作**，而是只显示创建信息就停止了。

## 问题原因
命令模板中虽然有"立即开始工作"的说明，但指令不够明确，导致 Claude 执行完创建线程操作后就停止，没有继续调用对应的角色 agent。

---

### 修复的文件
1. `.claude/commands/pm-start.md` - 产品经理启动命令
2. `.claude/commands/be-start.md` - 后端开发启动命令
3. `.claude/commands/fe-start.md` - 前端开发启动命令

### 修复方案

#### 明确的三步执行流程

**第1步：创建线程**
```javascript
mcp__thread-manager__create_thread({
  title: "[任务标题]",
  description: "[角色]任务 - [任务标题]",
  tags: ["role-tag"],
  switchTo: true
})
```

**第2步：简洁通知**
- ❌ 不再展示完整的 thread-manager message（太长）
- ✅ 只显示一行简短通知：
  ```
  ✨ 已创建[角色]线程："[标题]" (ID: [前8位])
  ```

**第3步：立即开始工作** ⭐ **关键修复**
- ✅ **不要停止！立即切换到对应角色**
- ✅ 读取角色的 agent prompt（`.claude/agents/xxx.md`）
- ✅ 以该角色身份执行任务
- ✅ 输出完整的工作成果
- ✅ 就像用户直接调用了 `/[角色] [任务]` 一样

## 注意事项

### 与 `/pm` 等直接命令的区别

| 命令 | 线程创建 | 立即工作 | 用途 |
|------|---------|---------|------|
| `/pm "任务"` | ❌ 不创建 | ✅ 立即工作 | 快速咨询 |
| `/pm-start "任务"` | ✅ 创建新线程 | ✅ 立即工作 | 完整任务 |

**共同点**：都会立即开始工作并输出完整成果

**区别**：`/pm-start` 会先创建一个独立线程来记录所有对话

### 线程恢复

如果需要完全的上下文隔离（推荐用于复杂任务）：

```bash
# 退出当前会话
exit

# 启动独立会话
clt abc123
# 或
claude --session-id abc-123-def-456
```

这样可以确保：
- 完全独立的对话历史
- 独立的 Git 分支
- 零上下文泄露
