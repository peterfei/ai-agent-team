## 🔑 核心技术决策

### 1. 嵌入模型: @xenova/transformers ✅

**为什么不用OpenAI？**
- ✅ **零成本** vs OpenAI每1K tokens $0.0001
- ✅ **隐私安全** - 数据本地处理
- ✅ **离线可用** - 无网络依赖

**性能如何？**
- 单次嵌入: 5-10ms ✅ 足够快
- 质量: MTEB Score 58.8 ✅ 中等，满足需求

### 2. 向量存储: 内存Brute Force（Phase 1）→ Qdrant（Phase 2）

**为什么不直接用Qdrant？**
- 🎯 **快速验证** - 避免过度设计
- 📉 **降低门槛** - 用户无需部署额外服务
- 🔄 **平滑升级** - 数据结构设计考虑迁移

**何时升级？**
```typescript
if (messages > 10K || latency > 50ms) {
  upgradeToQdrant();  // Phase 2自动触发
}
```

### 3. 实施策略: 同步嵌入 + 批量迁移

**新消息**: 创建时同步生成嵌入（+10ms可接受）
**历史消息**: 异步批量处理（50条/秒，不阻塞用户）

## 🎬 用户体验变化

### Before (v1.0)

```bash
# 用户必须记住确切关键词
/thread search "JWT"     # 只能找到包含"JWT"的消息
/thread search "认证"    # 找不到"authentication"相关的英文讨论
```

### After (v2.0 - Phase 1)

```bash
# 自然语言查询
/memory search "如何实现用户登录"
# ✅ 找到:
#   - "JWT认证实现"
#   - "Session管理方案"
#   - "OAuth2集成指南"
# 即使没有直接匹配"登录"关键词

# 语义理解
/memory search "authentication"
# ✅ 也能找到中文讨论的"认证""验证"相关内容
```

## ❓ 常见问题

### Q1: 为什么不直接做到Phase 3（语义记忆）？

**A**: 渐进式交付降低风险。Phase 1验证核心价值后再投入更多资源。

### Q2: 如果Phase 1效果不好怎么办？

**A**: 向后兼容，可直接回滚到v1.0，零损失。

### Q3: 用户需要额外配置吗？

**A**: 不需要。首次使用时自动下载模型（~23MB），后续离线可用。

### Q4: 性能会变慢吗？

**A**: 新消息创建增加10ms（几乎无感），搜索速度2-20ms（比SQL全文搜索更快）。

### Q5: 支持中文吗？

**A**: 支持，但质量略低于英文。Phase 2可切换多语言模型。
